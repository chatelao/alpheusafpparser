# Audit: Jackson Blackbird Integration State

This document provides an audit of the Jackson Blackbird module integration within the Alpheus AFP Parser as of June 2026.

## 1. Overview
The Jackson Blackbird module is the successor to the Afterburner module. It is designed for modern Java versions (8+) and leverages `java.lang.invoke.LambdaMetafactory` to generate high-performance, reflection-free accessors (getters, setters, and constructors) for serialization and deserialization.

In the context of the Alpheus AFP Parser, Blackbird is utilized to optimize the performance of the Jackson-based XML serialization path, particularly for structured fields and components that do not have a manual StAX-based fast-path.

## 2. Integration Details

### 2.1 Dependency Configuration
The module is included as an implementation dependency in `build.gradle.kts`:

```kotlin
dependencies {
    implementation("com.fasterxml.jackson.module:jackson-module-blackbird:2.17.2")
    // ...
}
```

### 2.2 Mapper Registration
Blackbird is registered in the central `JacksonXmlMapperProvider.java`. It is added to all primary `XmlMapper` instances, including the standard mappers and those configured for fragment mode and Woodstox backend:

```java
// src/main/java/com/mgz/xml/JacksonXmlMapperProvider.java

XML_MAPPER = XmlMapper.builder(new XmlFactory(AALTO_INPUT_FACTORY, AALTO_OUTPUT_FACTORY))
    .nameForTextElement("text")
    .enable(StreamWriteFeature.USE_FAST_DOUBLE_WRITER)
    .addModule(new BlackbirdModule())
    .build();

WOODSTOX_MAPPER = XmlMapper.builder(new XmlFactory(WOODSTOX_INPUT_FACTORY, WOODSTOX_OUTPUT_FACTORY))
    .nameForTextElement("text")
    .enable(StreamWriteFeature.USE_FAST_DOUBLE_WRITER)
    .addModule(new BlackbirdModule())
    .build();
```

The use of `.copy()` for fragment mappers ensures that the `BlackbirdModule` registration is preserved across all variants.

## 3. Performance Benefits
- **Reflection-Free Access:** By using `LambdaMetafactory`, Blackbird avoids the overhead of standard Java reflection when accessing POJO fields and methods during serialization.
- **Hot-Path Optimization:** This is particularly beneficial for the "fallback" path in `AfpJacksonXmlWriter.java`, where structured fields without manual fast-paths are handled via `JacksonXmlMapperProvider.getCachedWriter(...).writeValue(...)`.
- **Java 21 Alignment:** The integration is fully compatible with Java 21, the current target version for the Alpheus project.

## 4. Verification Proof (June 2026)
Verification was performed using a specialized test `BlackbirdVerificationTest.java` which inspects the internal `BeanPropertyWriter` instances generated by Jackson for Structured Field classes (e.g., `FND_FontDescriptor`).

The audit confirmed that:
- **Blackbird-specific writers** such as `com.fasterxml.jackson.module.blackbird.ser.StringPropertyWriter` and `BooleanPropertyWriter` are actively instantiated and used.
- These writers replace the standard `BeanPropertyWriter` for common primitive and String types, utilizing optimized bytecode generation for property access.
- For complex types where a standard writer is still used (e.g., `XmlBeanPropertyWriter` for collections), the registration of the module ensures that the overall serialization context is Blackbird-aware.

## 5. Current Status
The integration is **Complete**, **Verified**, and active in the production code path. It was originally implemented as part of the Phase 1 performance optimizations documented in `JSW_ROADMAP.md`.

## 6. Potential Risks & Limitations
- **Module Boundaries:** In strictly encapsulated environments (Java 17+ with JPMS), Blackbird may require `--add-opens` or `--add-exports` if it needs to access non-public members across module boundaries. Currently, Alpheus primarily serializes public or package-private members within its own packages, minimizing this risk.
- **JIT Compilation:** Like all bytecode generation techniques, there is a small warm-up period while `LambdaMetafactory` generates the accessors and the JIT compiler optimizes them.
